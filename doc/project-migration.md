# 迁移已有 AGENTS.md

首次写入遇到散文式 `AGENTS.md` 时（`projectAutoMigrate: true`），用**会话自身的模型路由**规划拆分。

## 提示词

模型不是只收到一句「拆成常驻区 + 主题文件」。`system` 里拼了三段内容：

1. **`lib/project-guide.ts` 的完整写法指南**（原文嵌入，约 3300 字符）；
2. **宽主题规则**：目标 3–6 个主题文件，最多 8 个（`DEFAULT_MIGRATION_MAX_FILES`），禁止一节一个文件、禁止 `all.md` / `notes.md` / `misc.md`，`summary` 必须回答「什么时候该读」；
3. **一个完整 few-shot**：18 个原文小节归并为 6 个宽主题文件的输入→输出示例。

`user` 消息只放待迁移的原文，避免模型把指南或示例误当成要迁移的文档。

## 宽主题为什么重要

只给「拆成常驻区 + 主题文件」的指令时，真实模型会按标题切片，产出 17 个索引行——索引从「什么时候该读」退化成目录，检索价值归零。`validatePlan` 因此把文件数上限做成硬闸门。

## 校验闸门

计划必须**全部**满足，任一不满足就整份放弃、什么都不写：

- 可解析（容忍 ```json 围栏）；
- 文件数不超过 `DEFAULT_MIGRATION_MAX_FILES`；
- 文件名过 `safeMemoryRel`（只能是 `memory/**.md`，无 `..`、无绝对路径、无 dotfile、无符号链接逃逸）；
- 每个文件有非空 `summary`，且不是 `all.md` / `notes.md` / `misc.md`；
- 内容过 `scanContent`（拦截凭据与提示注入载荷）；
- 常驻区 / 索引区 / 单文件都不超预算（索引区预算把**保留的旧条目和将被收养的孤儿文件**也算进去）；
- **原文每个标题都能在常驻区或某个主题文件里找到**（按结构比对，不是子串匹配）；
- 常驻区非空；
- 没有哪个主题文件原样包含了几乎整份原文；
- 结果总长不短于原文的 80%。

## 落盘顺序

1. 原文另存 `AGENTS.md.bak-<时间戳>`；
2. 写 `memory/<topic>.md`；
3. 重建 `AGENTS.md`：新常驻区 + 计划里的索引行 + 计划没提到的既有条目 + `memory/` 里未被索引的孤儿文件。

**重跑保护**：已有 `@memory/` 索引的文件属于迁移后形态，默认拒绝；即使 `force`，计划也不能静默取消任何存活主题文件的索引。

## 进度与排错

管理页点「迁移旧 AGENTS.md」后，宿主按真实阶段上报：

```
检查 AGENTS.md 形态 → 调用模型规划拆分 → 校验计划 → 写入主题文件与索引
```

页面显示操作名、阶段说明、所用模型、超时与已等待时间，同时禁用刷新与所有会改文件的按钮；同一时刻只允许一个迁移在跑（另一标签页或双击会被明确拒绝）。

每个阶段也写进 `<dshHome>/logs/persona-memory.log`：

```
admin: migrate <root> stage=planning 调用 p/model 规划拆分（最长 20 分钟）
```

失败/拒绝时页面保留卡片并给出可读原因，完成后显示新建主题文件数与 `.bak` 文件名。
